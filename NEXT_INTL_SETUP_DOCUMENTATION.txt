### 3. CONFIGURAÇÃO DE REQUEST
**Arquivo:** src/i18n/request.ts (movido de src/i18n.ts)
**Problema:** Configuração incorreta e localização errada
**Solução:** Reescrito seguindo documentação oficial

```typescript
import { getRequestConfig } from "next-intl/server";
import { hasLocale } from "next-intl";
import { routing } from "./routing";

export default getRequestConfig(async ({ requestLocale }) => {
  const requested = await requestLocale;
  const locale = hasLocale(routing.locales, requested)
    ? requested
    : routing.defaultLocale;

  return {
    locale,
    messages: (await import(`../../messages/${locale}.json`)).default
  };
});
```

**Problemas corrigidos:**
- Uso incorreto de validação de locale
- Caminho das mensagens incorreto
- requestLocale retornando undefined

export default async function RootLayout({

  children: ReactNode;

### 6. PÁGINAS (SERVER COMPONENTS)
**Arquivo:** src/app/[locale]/(main)/dashboard/default/page.tsx
**Problema:** Uso incorreto de useTranslations em server component
**Solução:** Troca para getTranslations e abordagem de server-side

```typescript
import { getTranslations, setRequestLocale } from "next-intl/server";

export default async function Page({ 
  params 
}: { 
  params: Promise<{ locale: string }> 
}) {
  const { locale } = await params;
  setRequestLocale(locale);
  
  const t = await getTranslations("dashboard.cards");

  return (
    <SectionCards 
      totalRevenue={{
        title: t("totalRevenue.title"),
        trending: t("totalRevenue.trending"),
        description: t("totalRevenue.description")
      }}
      // ... outras props com traduções
    />
  );
}
```

**Problemas corrigidos:**
- useTranslations não funciona em server components
- Passagem de função de tradução como prop (não serializável)
- Implementada abordagem Option 1 da documentação (mais performática)

## PRINCIPAIS MOTIVOS DOS ERROS

### 1. ESTRUTURA DE ARQUIVOS INCORRETA
- i18n.ts na raiz em vez de src/i18n/request.ts
- routing.ts em src/ em vez de src/i18n/routing.ts

### 2. PLUGIN NÃO CONFIGURADO
- next-intl precisa do plugin no next.config para funcionar
- Plugin procura por src/i18n/request.ts por padrão

### 3. USO INCORRETO DE HOOKS/APIS
- useTranslations em server components (deve usar getTranslations)
- useMessages() em layout server component (deve usar getMessages())

### 4. NEXT.JS 15 BREAKING CHANGES
- params agora é Promise<> em vez de objeto direto
- Necessário await params antes de usar

### 5. FALTA DE VALIDAÇÃO
- Layout não validava se locale é válido
- requestLocale retornando undefined

### 6. ABORDAGEM DE TRADUÇÃO INCORRETA
- Tentativa de passar função de tradução como prop
- Implementada abordagem server-side (Option 1) que é mais performática

WHY YAPD EXISTS

Running one Pi-hole is simple. Running several requires a source of truth.

Across home labs, VLAN setups, small offices, or family networks, managing redundant Pi-hole servers manually leads to silent drift and fragmented logs. YAPD makes multi-instance operations predictable.

Without YAPD

Scattered Manual Administration

  • Settings, ad-lists, and domain rules quietly drift between primary and secondary nodes.
  • DNS query investigation requires opening multiple browser tabs and correlating timestamps manually.
  • Blind replication scripts overwrite local state without pre-checks or rollback visibility.
  • No central audit trail of which rule changed, when, or on which Pi-hole instance.
With YAPD

Desired State, Drift Detection & Safe Sync

  • YAPD holds the canonical desired state and highlights exact drift before you apply changes.
  • Consolidated Dashboard and Queries Log aggregate traffic and client activity across all instances.
  • Per-instance concurrency coordination prevents overwhelming remote Pi-hole v6+ APIs.
  • Full audit history, operational notifications, and explicit TLS certificate validation.

Multi-Instance Dashboard

Monitor total queries, blocked requests, block percentages, and 24-hour client activity aggregated across all your Pi-hole v6+ nodes or filtered by individual instance.

Sync & Drift Detection

Compare live instance configurations against your central baseline. Spot out-of-sync nodes and reconcile changes safely with retries and pre-checks.

IPv4 & IPv6 Subnet Policies

Assign whole CIDR client networks (VLANs, IoT, Guest, Kids subnets) to Pi-hole filtering groups with per-instance previews and verified replication.

Unified Queries & Objects

Search DNS query history and centrally organize domains, groups, and ad-lists from one clean operational surface without switching tabs.

Security-First by Design

Built for LAN/VPN deployments with AES-256-GCM encrypted credentials, HTTP-only session cookies, CSRF protection, and explicit TLS trust per instance.

Audit-Focused Operations

Keep an explicit record of critical actions, sync jobs, configuration updates, and instance health alerts so nothing changes in the dark.

How YAPD Inspector Works

All domain analysis happens locally inside your browser with zero third-party telemetry. Paired securely via a temporary one-time code, detections are sent strictly to your own self-hosted YAPD instance on your private network.

Ads Ad servers, banners, and promotional media scripts
Tracking Telemetry, analytics beacons, and fingerprinting hosts
Third Party External cross-domain assets and embedded resources
User Inspector Domains manually flagged and submitted from the popup
Why is it installed via .ZIP instead of the Chrome Web Store?

As a privacy-first, open-source self-hosted tool built for homelabs, the extension is packaged and served directly by your YAPD container (and this repository) with no external store intermediaries.

PRODUCTION DEPLOYMENT

Up and Running in 3 Steps with Docker Compose

YAPD ships with a production-ready Docker Compose stack that bundles PostgreSQL 16 and the YAPD container with an internal Nginx proxy. No cloning or local compilation required.

01

Download the production compose.yml

Fetch the official compose file directly from the repository into your server or homelab host.

bash 
curl -O https://raw.githubusercontent.com/leufrasiojunior/yadp/main/compose.yml
02

Configure environment secrets & WEB_ORIGIN

Edit compose.yml to set your database password, cryptographic keys, and exact browser origin. Both PostgreSQL password variables must match.

Need strong keys right now? Generate random client-side secrets in your browser:
compose.yml (key placeholders) 
# In services.postgres.environment:
- POSTGRES_PASSWORD=change-this-password

# In services.yapd.environment:
- WEB_ORIGIN=https://yapd.example.com
- YAPD_POSTGRES_PASSWORD=change-this-password
- SESSION_SECRET=change-this-session-secret
- APP_ENCRYPTION_KEY=change-this-encryption-key
03

Start the stack & open the dashboard

Launch the containers in detached mode. YAPD automatically runs database migrations on startup and publishes HTTP and HTTPS endpoints.

bash 
docker compose up -d
HTTPS (Direct LAN / VPN) https://<your-ip>:48443

Served via internal Nginx with an auto-generated self-signed TLS certificate.

HTTP (External Reverse Proxy) http://<your-ip>:48080

Ideal upstream target when terminating public TLS in Nginx, Caddy, or Nginx Proxy Manager.

ARCHITECTURE & SECURITY BOUNDARIES

Engineered for Private Networks with Real Application-Level Controls

YAPD is a TypeScript monorepo separating presentation (Next.js App Router + Shadcn UI) from canonical domain logic (NestJS + Prisma + PostgreSQL). Sensitive operations never run in the browser.

  • Zero Hardcoded Admin Credentials: No fixed default bootstrap account; administrative setup is explicit and protected.
  • Encrypted Pi-hole Secrets (AES-256-GCM): Instance passwords and sensitive tokens are encrypted at rest and never exposed in read payloads.
  • Explicit Certificate Trust: HTTPS connections validate TLS strictly by default, allowing self-signed certificates only per explicitly consented instance.
  • HTTP-Only Sessions & Anti-CSRF Guard: Cookie-backed sessions with rate limiting, lockouts, and mandatory CSRF header verification on mutating routes.
